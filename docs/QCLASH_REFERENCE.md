# qClash reference assessment

Reference repository: [josephpei/qClash](https://github.com/josephpei/qClash), pinned to commit [`0857e85c6fbe72fa8bda00f4a083e0fe3c33849c`](https://github.com/josephpei/qClash/tree/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c). The local read-only reference is `.cache/references/qClash`. This assessment inspected source, not a running qClash installation; the reference code was not built or executed, and no code or assets were imported.

The repository includes the GNU GPL version 3 license text in its [LICENSE](https://github.com/josephpei/qClash/blob/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c/LICENSE). The changes below were independently implemented in clash-qt.

**qClash is a useful native Qt workflow reference, not a substitute for the Verge Rev capability target.** It demonstrates a compact Widgets application around a separate Clash process. Its tray workflows and Linux integration suggest practical improvements to clash-qt. Its process, networking and build implementations also contain concrete weaknesses that should not be reproduced. The protocol list in its README describes the underlying Clash core; it does not establish that qClash implements the modern mihomo management features in the [Verge Rev comparison](FEATURE_PARITY.md).

## Architecture comparison

qClash uses C++17, Qt Widgets, a Designer `.ui` main window, programmatic dialogs/widgets, Qt Network/WebSockets, yaml-cpp, QSettings, QProcess and a bundled SingleApplication dependency. The main objects are global/singleton `Configurator`, `ClashCore` and `HttpUtil`, with static `ClashApi` methods. The main window coordinates startup, subscriptions, configuration changes, proxy controls, traffic and tray menus. [Build definition](https://github.com/josephpei/qClash/blob/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c/CMakeLists.txt), [entry point](https://github.com/josephpei/qClash/blob/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c/src/main.cpp), [main window](https://github.com/josephpei/qClash/blob/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c/src/mainwindow.cpp).

clash-qt already follows the relevant native direction: C++20/Qt6 Widgets, separate mihomo child process, yaml-cpp, Qt network APIs and native tray. Its [application context](../src/app_context.h), [client](../src/core/mihomo_client.h), [profile store](../src/core/profile/profile_store.h), [process owner](../src/core/process/core_process.h) and page classes provide more explicit ownership and narrower responsibilities. QJSEngine is used for enhancement scripts; it is not a QML or WebView user interface. Keep these boundaries instead of replacing them with qClash's singleton/static service structure.

## Source pitfalls that should not be adopted

1. **Controller credentials cross request boundaries.** `ClashApi::setSecret` sets the shared `HttpUtil` bearer token; `HttpUtil::request` attaches it without checking the request origin. Subscriptions, GitHub release queries and geodata downloads also use that singleton. Preserve distinct controller/external request paths. This is a source-level finding, not a claim that any real credential was transmitted during this audit. [API](https://github.com/josephpei/qClash/blob/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c/src/core/clashApi.cpp), [HTTP implementation](https://github.com/josephpei/qClash/blob/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c/src/utils/httputil.cpp), [external downloads](https://github.com/josephpei/qClash/blob/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c/src/utils/utility.cpp).

2. **Reconnect behavior is not a robust template.** `WsClient::onConnected` connects the message handler on every connection, reconnect is immediate, and `reset(newUrl)` does not update the URL used by future reconnects. The traffic socket is opened with a URL rather than an authenticated request. clash-qt's one-handler-per-socket, authenticated reconnect/backoff and endpoint epochs address these concerns. [qClash WebSocket helper](https://github.com/josephpei/qClash/blob/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c/src/utils/wsclient.cpp), [traffic socket construction](https://github.com/josephpei/qClash/blob/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c/src/mainwindow.cpp).

3. **System proxy support must preserve user state.** qClash's reset helpers clear/disable settings rather than restoring a captured prior configuration; its macOS service names are hard-coded to `Wi-Fi` and `Enternet`, and its Windows helper has no settings-change broadcast. Its `NetworkProxy::operator==` returns after comparing only the mode, leaving host/port comparisons unreachable. These are reasons to retain clash-qt's ownership/restoration approach and platform tests. [qClash proxy helper](https://github.com/josephpei/qClash/blob/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c/src/utils/networkproxy.cpp), [comparison operator](https://github.com/josephpei/qClash/blob/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c/src/utils/networkproxy.h).

4. **Declared portability does not establish working builds or packaging.** qClash's `USE_QT6` branch discovers Qt6, but later code calls `qt5_*` functions and links `Qt5::*` targets unconditionally. The Windows 32-bit binary assignment is missing a semicolon. The Linux executable install rule is commented out while the desktop entry points to `/opt/qClash/qClash`. The macOS translator looks in `Resources/lang`, while its translation install destination is `../Resources`. These observations were not validated by compiling or installing the reference; they are concrete inconsistencies to avoid in new build rules. [CMake](https://github.com/josephpei/qClash/blob/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c/CMakeLists.txt), [binary selection](https://github.com/josephpei/qClash/blob/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c/src/core/clashCore.cpp), [translation loading](https://github.com/josephpei/qClash/blob/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c/src/main.cpp).

5. **Menu construction must be read-only and unbounded by fixed arrays.** qClash allocates 99 profile/group slots, then indexes group menus while iterating the returned groups without a matching bounds check. Building group menus also calls the selection API for the saved node. Independently implemented menus should neither overflow on large configurations nor mutate the controller merely because a menu is displayed. [qClash menu storage](https://github.com/josephpei/qClash/blob/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c/src/mainwindow.h), [menu population](https://github.com/josephpei/qClash/blob/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c/src/mainwindow.cpp).

6. **Keep deterministic regression tests.** qClash's HTTP test calls the public `httpbin.org` service. clash-qt's local HTTP fixtures and temporary filesystem tests can verify authentication, stale responses, failures and backup rejection without depending on third-party uptime or exposing production data. [qClash HTTP test](https://github.com/josephpei/qClash/blob/0857e85c6fbe72fa8bda00f4a083e0fe3c33849c/test/utils/http_test.cpp), [clash-qt tests](../tests).

The most useful immediate alignment is the everyday tray/shell workflow, followed by geodata maintenance and distributable desktop integration. KDE support and translations are meaningful follow-up scope. None of these should weaken the asynchronous, validated, state-preserving behavior added by the clash-qt audit, or change the still-incomplete Verge Rev parity assessment.

## Changes and validation in this pass

- Applied the tray, shell environment, subscription URL, group-order and GEO update alignments above. The existing asynchronous networking and state-preserving design remains in place.
- Added tray regression coverage for encoded node names, stale selections, automatic/read-only groups, submenu lifetime and credential-free POSIX/PowerShell commands. Controller tests cover configured group ordering and authenticated/deduplicated GEO update success/failure. Runtime tests cover URL edits and stale subscription responses.
- All seven CTest suites passed after the application build (6.75 seconds). GEO updates were tested with local HTTP fixtures; no real database download or system proxy change was triggered.
- The install audit found that installing only the executable stripped access to yaml-cpp. Qt dependency deployment and its modular-library search path were added in response; the installed macOS app now starts successfully with `--version` and reports `clash-qt 0.1.0`. Dynamic-loader tracing confirms that Qt and yaml-cpp load from its own `Contents/Frameworks` directory. This is a local installation check, not clean-machine or notarized-release validation.
